# Спецификация: приложение «Матрица парных сравнений», версия 1

17.10.2026 · основа: [requirements.md](../requirements/requirements.md)

## 1. Объём версии 1

Один пользователь, одна матрица элементов (до 30), оценка «лучше / равно / хуже», опрос обеих сторон пары (отключаемый), поиск противоречий с повторным сравнением, рейтинг и веса, сохранение проекта в файл, экспорт в PDF. Работа офлайн на ноутбуке и телефоне (PWA).

Не входит в версию 1: шкала Саати 1–9, несколько критериев, иерархия, анализ чувствительности, синхронизация.

## 3. Модель данных

```ts
type Answer = 'better' | 'equal' | 'worse'; // оценка «первый элемент пары относительно второго»

interface Item { id: string; name: string; note?: string }

interface Response {
  first: string;      // id элемента, показанного первым
  second: string;     // id второго элемента
  answer: Answer;
  round: number;      // 1 — основной опрос, 2+ — повторные сравнения
  answeredAt: string; // ISO-дата
}

interface Settings {
  askReverse: boolean; // опрашивать обратные пары; по умолчанию true
}

interface Project {
  schemaVersion: 1;
  id: string;
  name: string;
  createdAt: string;
  updatedAt: string;
  settings: Settings;
  items: Item[];
  responses: Response[]; // полная история ответов
  resolutions: { a: string; b: string; value: Answer; by: 'recompare' | 'manual' }[];
}
```

Файл проекта: JSON с расширением `.pairwise.json`. Импорт проверяет `schemaVersion` и структуру.

## 4. Алгоритмы

### 4.1. Число сравнений (счётчик)

- `askReverse = true`: n(n−1); для 30 элементов 870.
- `askReverse = false`: n(n−1)/2; для 30 элементов 435.

Счётчик обновляется при вводе элементов и при переключении настройки; на экране сравнения показывается прогресс «выполнено из всего».

### 4.2. Порядок пар

1. Все неупорядоченные пары {A, B} перемешиваются (алгоритм Фишера–Йетса), у каждой случайно выбирается, какой элемент показан первым.
2. Если `askReverse = true`, после первого прохода идёт второй: обратные пары (B, A) в новом случайном порядке. Последняя пара первого прохода и первая пара второго не должны быть одной и той же парой.
3. Порядок сохраняется в проекте, чтобы прерванный опрос продолжался с того же места.

### 4.3. Значение пары и прямые противоречия

Для пары {A, B} приводим ответы к виду «A относительно B» (ответ на (B, A) зеркалится: better ↔ worse).

- Ответ один (`askReverse = false`) или два совпадающих: пара согласована.
- Два ответа не совпадают: **прямое противоречие**, пара спорная.
- Если по паре есть запись в `resolutions`, используется она.

Результаты рассчитываются, только когда у каждой пары есть согласованное значение. Спорная пара разрешается повторным сравнением (обе стороны заново) или вручную выбором значения.

### 4.4. Рейтинг и веса

Матрица M: M[A][B] = 1 (A лучше), 0,5 (равно), 0 (хуже); M[B][A] = 1 − M[A][B].
Очки: s_A = Σ M[A][B]. Вес: w_A = s_A / (n(n−1)/2). Места по убыванию очков, равные очки дают общее место.

### 4.5. Циклические противоречия и согласованность

Для каждой тройки элементов (до 4 060 троек при n = 30) проверяется, можно ли расставить три элемента в ранжирование (с возможными равенствами), которое даёт все три ответа.

- **Строгий цикл**: A > B > C > A.
- **Нестрогое противоречие**: с участием «равно», например A > B, B > C, A = C.

Коэффициент согласованности Кендалла: ζ = 1 − d/d_max, где d — число строгих циклов, d_max = (n³ − n)/24 при нечётном n и (n³ − 4n)/24 при чётном. ζ = 1 означает полную согласованность. Источник: Kendall M.G., Babington Smith B. (1940). On the method of paired comparisons. *Biometrika*, 31(3/4), 324–345. https://doi.org/10.2307/2332613

Нестрогие противоречия в ζ не входят, но показываются в списке.

### 4.6. Выбор пар для повторного сравнения

Для каждой пары считается число циклов (строгих и нестрогих), в которых она участвует. Пары выдаются на повторное сравнение по убыванию этого числа; после каждого ответа анализ пересчитывается. Пользователь может остановиться в любой момент.

Допущение: порог «приемлемой» согласованности в методике Кендалла не задан, поэтому приложение не блокирует результат по ζ, а показывает число циклов и ζ.

## 5. Экраны (сначала телефон, затем ноутбук)

1. **Проекты**: список, создание, открытие, импорт файла, удаление с подтверждением.
2. **Элементы**: добавление, переименование, удаление, порядок; переключатель «Опрашивать обратные пары»; счётчик «N элементов → K сравнений». Если ответы уже есть, при изменении списка показывается, какие пары добавятся или удалятся.
3. **Сравнение**: вопрос «Что важнее?» с двумя элементами и тремя кнопками: «A важнее», «Равны», «B важнее»; индикатор прогресса; «Назад» для исправления последнего ответа; автосохранение после каждого ответа.
4. **Проверка**: прямые противоречия, строгие и нестрогие циклы, ζ; кнопка «Повторно сравнить спорные пары»; ручное разрешение пары.
5. **Результаты**: таблица (место, элемент, очки, вес %); матрица с цветовой разметкой и горизонтальной прокруткой на телефоне; ζ и число циклов; кнопки «Сохранить файл проекта» и «Экспорт в PDF».

Общие требования: интерфейс на русском; работа офлайн; напоминание сохранить файл проекта, если он не сохранялся после последних изменений.

## 6. Содержание PDF

Название проекта, дата, список элементов, настройки опроса, таблица результатов, матрица, ζ и число циклов, список неразрешённых нестрогих противоречий (если есть).

## 7. Контрольные примеры (эталон для тестов)

Расчёты проверены скриптом.

**Пример 1, согласованный.** Скорость, Стоимость, Вес. Скорость > Стоимость, Скорость > Вес, Стоимость = Вес.

| Элемент | Очки | Вес |
|---------|------|-----|
| Скорость | 2 | 66,7% |
| Стоимость | 0,5 | 16,7% |
| Вес | 0,5 | 16,7% |

Циклов 0, ζ = 1.

**Пример 2, цикл и прямое противоречие.** Скорость, Стоимость, Вес, Надёжность.
Ответы: Скорость > Стоимость, Стоимость > Вес, Вес > Скорость, Надёжность > Скорость, Надёжность > Вес. По паре Надёжность–Стоимость: (Надёжность, Стоимость) = «лучше», (Стоимость, Надёжность) = «лучше».

Ожидается:
- прямое противоречие по паре Надёжность–Стоимость, результаты не рассчитываются;
- после повторного сравнения с итогом Надёжность > Стоимость: Надёжность 3 очка (50%), остальные по 1 очку (16,7%);
- один строгий цикл Скорость > Стоимость > Вес > Скорость; d_max = 2, ζ = 0,5;
- первыми на повторное сравнение предлагаются три пары цикла.

**Пример 3, нестрогое противоречие.** A > B, B > C, A = C.
Очки: A 1,5 (50%), B 1 (33,3%), C 0,5 (16,7%). Строгих циклов 0, ζ = 1, одно нестрогое противоречие.

**Счётчик.** n = 3 → 6 / 3; n = 20 → 380 / 190; n = 30 → 870 / 435 (с обратными парами / без них).

## 8. Изменения версии 1.1 (18.10.2026, по замечаниям пользователя)

1. Массовое добавление: поле принимает список (по одному на строке или ячейки таблицы), маркеры списка убираются, повторы пропускаются, лишнее сверх 30 не добавляется.
2. Описание элемента (`Item.note`): редактируется по нажатию на элемент, показывается на кнопке при сравнении и в PDF.
3. Экран «Проверка»: итоговый статус простым языком; согласованность в процентах (ζ Кендалла); строгие и нестрогие противоречия объединены в свёрнутый блок «Несогласованные тройки» с пояснением.
4. Экран «Результаты»: одна матрица с названиями элементов в заголовках, столбцами «Очки» и «Вес»; сортировка по элементу, очкам и весу в обе стороны; строки и столбцы матрицы следуют одному порядку. PDF построен так же (до 8 элементов названия в заголовке, больше — номера и альбомная страница).
5. Кнопки сравнения содержат только название элемента (и описание), «Равны» — отдельной кнопкой.
